# project-bootstrap

> **给项目「立规矩」的 Agent Skill** —— 让任何一个 Agent（或下一个对话）接手你的项目时，都知道**东西放在哪、规矩写在哪、事情推进到哪**。

```
动手之前                          动手之后
我的项目/                         我的项目/
├── 资料.docx                     ├── AGENTS.md    ← 规矩（新会话开场先读）
├── 笔记.md                       ├── MEMORY.md    ← 进度与决策（接手先读）
├── 最终版2.html                  ├── PRD.md       ← 需求基准（写完先停下来等你审）
└── 旧版/                         └── ROADMAP.md   ← 计划与关卡（问题没答案不放行）
```

## 它做什么

| 场景 | 输入 | 产出 |
|---|---|---|
| **新项目 · 从零** | 一句话说清要做什么 | 骨架文档（`AGENTS` ／ `MEMORY` ／ `USER` ／ `SOUL` ／ `PRD`）＋ git 初始化，然后**停在 PRD 等审核**；审核通过才写 `ROADMAP` 开工 |
| **新项目 · 照着样板做** | 一个已有的样板项目 | 抽骨架（母版 ／ 工具脚本 ／ 目录与文档结构）→ 改接线（先列清单过目）→ **真跑校验**；不搬内容数据与进度文档 |
| **老项目 · 回头对齐** | 一个已经在跑的项目 | **只读取证** → 出差异清单交审核 → 一次改到位（动了目录就逐个修链接并实测） |

**`engineering/` 工程区立项即建**（装工具脚本与项目进度页的投影脚本），`content/` 内容区按需，`CONTRACT.md` 有线间接口才建 —— 目录与文档**按需生长**。

## 这一版新在哪（v1.2 → v1.3）

| 新能力 | 你会在什么时候感觉到 |
|---|---|
| **协作方式**：分清「主控 ／ 执行」两个角色位 | 多开对话时，谁管进度、谁干活、提示词怎么传，都有明文 |
| **授权三层**：可直接改 ／ 先请示 ／ 一律先问 | 它不会擅自装软件、改目录结构、把东西发到外面 |
| **收尾两道**：A 自查（引用可达 ／ 旧口径零残留 ／ 清单＝实物）＋ B 追平（进度文档与页面） | 交付前替你查一遍“还有没有停在上一版的地方” |
| **复验**：主要任务完成后另派一路独立核对 | 结论不是它自己说自己对 |
| **提问方式**：一次问完；关键选择给 2–3 个选项 ＋ 推荐 ＋ 各自代价 | 少来回拉扯，你直接选 |
| **进度页**：立项即建，页面数据从 `ROADMAP.md` 投射 | 随时能看到“到哪了”，不用追着问 |
| **开场读最小集**（v1.3）：只读 `AGENTS` §一～§三 ＋ `MEMORY` §2 顶部两条，其余按需查 | 新会话起步更快，不把上下文烧在读文档上 |

## 安装

把这句话交给支持安装 Skill 的 Agent：

```text
请帮我安装这个 Skill：https://github.com/Columbinagi/project-bootstrap
```

或者用命令安装：

```bash
npx skills add Columbinagi/project-bootstrap
```

装好就能用，无需额外配置。

**怎么确认装对了**：在任意项目文件夹里新开对话，说「用 project-bootstrap 帮我起个项目骨架，**先只出清单、别动文件**」。
它先复述理解并提问、给出清单而**不直接动手**，就说明规矩已经生效。

## 使用

在**项目文件夹里新开一个对话**，直接把要求告诉它，例如：

- "用 project-bootstrap 帮我在当前这个文件夹里起一个新项目。"
- "照 `E:\我的老项目` 的样子，在这个文件夹里派生一个新项目。"
- "把这个已经在跑的项目按规范回头对齐，先别动手，列出差异清单给我批。"
- "先只出清单，这一轮不要改任何文件。"
- "project-bootstrap 更新了，检查本项目是否需要跟随更新 —— 先只读取证。"

有现成的资料、样板项目或截图，一起交给它；没有也能开始，只有不清楚要交付什么时它才会问你。

**它实际会怎么走**（拿"起一个新项目"举例）：

> 你说「帮我在这个文件夹里起一个新项目」→
> ① 它先**复述理解**，把缺的信息一次问清（项目做什么、有没有样板、建在哪），**等你确认才动手**；
> ② 建骨架文档（`AGENTS` ／ `MEMORY` ／ `USER` ／ `SOUL` ／ `PRD`）＋ `git init`；
> ③ 写完 `PRD.md` **就停下** —— 把前提假设逐条列出来给你审；
> ④ 你审过，才写 `ROADMAP.md`（关卡与阶段），然后开工；
> ⑤ 之后每次会话**开场只读最小集**（`AGENTS.md` §一～§三 ＋ `MEMORY.md` §2 顶部两条与 §4；其余按需查），对着「产物长出来的顺序」表自查"现在该长什么"。

> 不适合用的场合：只是聊项目结构、整理文件夹、改个名之类的琐事，或者还没决定要立一个项目。

## 它怎么想

1. **先把流程立起来，再动手。** 分几步、每步产出什么、谁拍板、什么算做完 —— 写不出流程，说明还没想清。
2. **目录按需生长。** 真有东西装才建目录；"以后可能用到"不是理由。
3. **关卡卡的是「问题有没有答案」，不是「文件存不存在」。** 前置问题没答案就不放行。
4. **`PRD.md` 写完就停。** 等你审核通过才写计划、才开始干活。
5. **动过的东西必须有实测。** 改过目录就逐个修链接并实测；口径变了就全库查旧说法有没有残留。
6. **口径类决定由你拍板，它只给推荐和代价。** 验收标准、判定口径这类会改变结论的事，不替你决定。
7. **你拍板优先于硬规矩 —— 但会写明代价。** 你要保留不合硬规矩的做法可以，清单里会写清"由你决定"和这么做的后果。

## 它会产出什么

**按需生长，不预建空目录**：

| 文件 | 作用 | 什么时候长出来 |
|---|---|---|
| `AGENTS.md` | 项目规则总纲（新会话开场先读） | 立项 |
| `MEMORY.md` | 进度与决策索引（接手先读） | 立项 |
| `USER.md` | 用户偏好与雷区 | 立项 |
| `SOUL.md` | 协作准则（按区附写作纪律 ／ 编码准则） | 立项 |
| `PRD.md` | 需求基准（改动先与它比对） | 立项 |
| `ROADMAP.md` | 计划与关卡 | PRD 审核通过后 |
| `CONTRACT.md` | 线间字段契约（**有线间接口才建**） | 出现线间接口约定时，**产出之前** |
| `ACCEPTANCE.md` | 验收记录（逐条对 PRD 的实测值） | 进入验收前 |
| `engineering/` | 工程区：工具脚本 ＋ 进度页投影脚本 | **立项即建** |
| `docs/项目进度.html` | 给人看的进度页（投影件：`stage`／`stages` 不手改，其余字段手改） | **立项即建** |

关卡：**G1 可以开始设计 → G2 可以开始动手 → G3 可以进入主体制作 → G4 可以验收**。

## 需要什么

看你的 Agent 能做什么：**能读写文件、能执行命令**（建目录 ／ git ／ 写文件），才能把骨架建起来；**能提问**，才能采集偏好。缺了哪一项，它会说明哪部分没做。

**git 可选**：没有 git 就跳过版本库步骤，并在收尾时如实说明。它不绑定某个 Agent 工具或模型，但主要在 DSH 上开发与验证，其他工具与模型没有逐一试过。

## 数据与隐私

它不上传任何内容，也不保存密钥 —— 所有产出（文档、目录、git 提交）都只落在你的项目文件夹里；要你看的东西直接在对话里给你，不会替你对外发送。

## 其他工具怎么装

把 `SKILL.md` 与 `references/` 放进那个工具的技能目录即可。例如 **DSH 桌面端**（上面的 CLI 暂时不支持它）：

```bash
git clone https://github.com/Columbinagi/project-bootstrap.git "%USERPROFILE%\.dsh\skills\project-bootstrap"
```

> **一处只留一份**：多个工具要共用时，用**符号链接**指向同一份，不要复制出第二份 —— 复制就是两份正文，迟早对不上。
