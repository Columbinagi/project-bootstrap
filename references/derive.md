# 从样板派生 — 场景一「**照样板做**」这一支（有样板时）

> **仅在用户明确要求时执行**（"照 X 的样子做一个"、"从这份母版派生一个新项目"）。
> 它**不是第三个顶层模式，也不是"第二个使用场景"** —— 它是**场景一 · 新项目**里的
> **一个起点分支**（新项目从哪儿起步：**空白起步** ／ **照样板做**）。
> **两条路在同一个「停下来等审 PRD」汇合**：复述确认、建文件夹、`git init`、写 PRD、
> **PRD 审核通过前不写 `ROADMAP.md`**、不预建目录 —— **主流程的纪律一条不少**
> （拆成独立模式 = 同一套纪律写两份 = 漂移源）。
> **照样板做省的是搭骨架的工，不是立规矩的环节** —— 派生项目一样要写 PRD、一样要等审。
> 与 `SKILL.md` 第 2 / 4 步唯一的差别：**不建空文件夹，而是「抽样板 → 改接线 → 跑校验」。**

## 一、为什么样板本体不进 skill

样板（引擎母版 / 站点骨架 / 文档骨架）是**另一个项目的产物**。把它复制进 skill，
立刻就有了**两份要同步的东西** —— 样板与源项目会各自演化，
**"两份对着改"正是本 skill 全书在治的病**。

所以本 skill 只放三样：**① 样板在哪里的指针 ② 派生后必须改哪几处接线 ③ 改完怎么验。**

## 二、前置：先问清**三件**，别猜

| # | 问 | 为什么 |
|---|---|---|
| 1 | **样板版本号**（路径 ＋ 版本 / 提交号） | 样板多半还在被持续使用，**不记版本就说不清派生自哪一版** |
| 2 | **派生范围** | 整站骨架 / 引擎母版 / 只要文档骨架 —— 决定"抽样板"的范围 |
| 3 | **新项目建在哪** | 走 `SKILL.md` 第 2 步（默认根目录在 `USER.md`） |

> **样板还在持续使用时再加问一件**：样板里哪些是**共用件**、如何回流（见第六节）——
> 别默认"派生完就各自飞"。

## 三、抽样板（**不是复制文件夹**）

1. **先盘点接线点**：对着样板找出第四节那些位置，**列出来再动手**
2. **只取可复用的骨架部分** —— 引擎母版、工具脚本、目录与文档骨架；**不搬**：
   - **内容数据** —— 内容是新项目的生命，本来就该全新写；
   - **进度文档** —— 样板的 `MEMORY` / `ROADMAP` / 待办一律清空重写；
   - **git** —— 派生件是新项目，**新仓库**；
   - 源项目其余私有 / 历史数据一律不带
3. **不预建**：只取"现在就有内容"的部分（空目录不复制，见 `SKILL.md` 贯穿纪律）
4. `git init`：**不沿用源项目的 `.git`**
   （要延续历史的那种动作叫迁移 / 分支，不是派生）

## 四、改接线清单（逐条过，不许跳）

| # | 接线点 | 改什么 |
|---|---|---|
| 1 | 项目名 / 标题 / 元数据 | 页面标题、包名、署名 |
| 2 | **硬编码路径** | 绝对路径、含源项目名的相对路径 —— 判据：**整个文件夹搬走还能跑** |
| 3 | 入口 / 产物文件名 | 产物**落点固定**（由源生成 → `dist/`，手写即交付 → `docs/`；见 `versions.md` §八）；`dist/` 里的**文件名保持稳定** —— 确要改名就放最后一步并确认（改名 / 移位会断链，按 `realign.md` 第 4 步修链接） |
| 4 | 配置与忽略规则 | 仓库配置、构建配置、`.gitignore` |
| 5 | **契约 / 字段定义** | 沿用 → 写明"沿用自样板 <版本>"并冻结；**改动 → 进 `PRD.md` 变更记录**（见 `versions.md` §十） |
| 6 | 指向源项目的引用 | 链接、说明文字、"见 X 项目"之类的注释 |
| 7 | **样板自带的进度文档** | `MEMORY` / `ROADMAP` / 待办 —— **必须清空重写**；留着源项目的进度比缺文档更糟 |
| 8 | **校验 / 回归用例里写死的样例标识** | 主题 id / 分类 id / 词条 id 之类 —— **它躲得过第 2 条**（路径都是相对的、搬走能跑），**只在跑校验时才炸**；派生后按新项目的真实标识改写，或改成从数据推导 |

> 清单**先列出来交用户过目**，再动手改。

## 五、跑校验（改完必须实际跑一遍）

- **样板的验法**：样板自带的校验 / 自检命令（若有）—— 照跑
- **本 skill 的验法**：`PRD.md` **已经写了** → 对它的 §六 验收基准逐条；**还没写**（派生阶段常见）→
  先跑**样板自带的校验** ＋「**整个文件夹搬走还能跑**」＋「产物与源一致」；**PRD 写完后要再对着 §六 合一遍**
- **"文件都在"不算过** —— 判据必须能被外部核对（见 `SKILL.md` 第 5 步）
- **验法会骗人**：路径类接线错了，在"搬走还能跑"这一步就暴露；
  **写死的样例标识（§四 第 8 条）只在跑校验时才炸** —— 所以「抽样板 → 改接线」之后**必须真的跑一遍校验**
- 跑不通就说跑不通
- **跑完校验 ≠ 开工**：派生件仍要走**写 `PRD.md` → 停下来交使用者审核**这一关（审过才写 `ROADMAP.md`）——
  **照样板做没有"跳过审 PRD"的快捷方式**

## 六、派生之后的漂移

- 派生件是**新项目**：它的规矩从自己的 `AGENTS.md` 起，**不再回读源项目**
- 若希望两边长期一致 → 那说明共用件该**独立成一个项目（母版）**，两侧都用指针指过去；
  **不要靠"记得两边都改"** —— 那是靠记忆维持的契约，迟早断
