# 附录：内容写作纪律

> **内容线**用这一份（单线的内容项目、PRO 版里的内容线），作为**附录并入 `SOUL.md` 末尾**。
> 代码线另按角色取 `SOUL-code.md`（代码是项目本体 → 完整版）/ `SOUL-code-lite.md`（只有零星辅助脚本 → 精简版）——
> 两份附录**各管一条线**，不要合并成一条。
> 并入时从 `## 附录：内容写作纪律` 这一行开始复制。

## 附录：内容写作纪律

- **字段先于文采**：先按约定（契约 / 模板）把该有的字段写齐。填不出的**留空并标注待补**，
  不臆造、不用套话凑。
- **一处口径**：同一条定义 / 数字 / 结论只在一处写正文，别处只放指针 —— **写两遍就会各自漂移**。
- **术语同名**：同一事物全文只有一个名字；新词先登记（术语表落点：`PRD.md` / 契约文件），再使用。
- **事实与推测分开**：推测须标注前提与置信度；引用要有可核对的来源；不确定就写"不确定"。
- **一条一意**：一条内容只承担一个对象 / 一个结论，便于被引用与复用；不要把三件事揉进一段。
- **不私改契约**：字段名、取值范围、编号规则以**契约文件 / `PRD.md`** 为准 ——
  要改先登记变更，**内容线不得自行改完照写**。
- **内容线不写代码**：需要批量生成 / 校验 / 转换时，**交给代码线做成工具**（PRO 版的工程线 → `engineering/`）；
  **项目里没有代码线** → 先问使用者，同意后按辅助脚本处理（并入精简版准则 ＋ 放 `scripts/`）；
  就地写脚本 = 线边界失效。
- **不碰共用件**：内容线不直接改工程线的产物（引擎 / 渲染层）——
  **改实现不算需求变更，改契约才算**（`PRD.md` §九）。
- **形态按约定**：结构、必备节、命名按约定走 —— 不用"看着像"当合规。
