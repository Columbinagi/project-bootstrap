## 二、目录结构

> **只画骨架文档的固定位置。** `PRD.md` 在第 5 步写（**不建空文件**）；其余目录什么时候长见 §三 —— **不预建空目录**。

```
<项目名>/
├── AGENTS.md        本文件：背景 + 领地 + 目录 + 产物顺序 + 写入规范
├── MEMORY.md        进度与决策索引（接手先读；最新在上）
├── USER.md          使用者画像与雷区
├── SOUL.md          协作准则（＋按区并入的准则附录）

├── .gitignore
└── .git/            版本库（无 git 环境则无此项）
```

**骨架目录里面怎么分**（方向，不是硬规则）：一层一个维度 ／ 同类同处 ／ 能平铺就不分层 ／
深度 ≤ 2–3 层 ／ 不留 `misc` `其他` `temp` 兜底目录 ／ 内部命名中英文都行但同层保持一致。

**`scripts/` 不存在**：辅助脚本一律进 `engineering/` —— 一个职能只留一个落点。

## 四、文档写入规范

| 什么时候发生 | 写进哪份 | 怎么写 |
|---|---|---|
| 需求 / 约束 / 验收确定或变更 | `PRD.md` | 改对应节 ＋ 变更记录加一行 |
| 接口 / 契约确定或变更 | `CONTRACT.md`（或 `PRD.md` 对应节）＋ `PRD.md` 变更记录 | 产出前先定并冻结；**改实现不登记，改契约才登记** |
| 阶段推进、关卡通过 | `ROADMAP.md` | 改状态列；卡点变了改「当前卡点」节 |
| 任何进展 / 决策 / 待办变化 | `MEMORY.md` | 按节追加到顶部（最新在上），**不覆盖旧条目** |
| 目录 / 命名 / 规则 / 工作流变化 | `AGENTS.md` | 改对应节，同时检查 §二、§三 |
| 使用者偏好 / 雷区变化 | `USER.md` | 改对应节 |
| 任务结论（同主题续更） | `notes/{任务名}_结论_{YYYYMMDD}.md` | 只追加；结论被推翻时新条目写明「**取代第 N 条**」 |
| 分析 / 论证 / 盘点（只增不改） | `notes/{YYYYMMDD}_{子主题}.md` | 新建文件；已有的一律不改 |
| 交付文档 | `docs/{名称}_{YYYYMMDD}.html` | 默认单文件 HTML（`USER.md` 另有偏好从其偏好）；**已有文件不改名** |
| 完工实测值 | `ACCEPTANCE.md` | 逐条对 `PRD.md` 验收基准 |

> **编码**：文本一律 **UTF-8 无 BOM** —— BOM 会让解析器读不到文件头（配置 / 入口文件直接失效）。
> 唯一例外：工具要求带 BOM 的脚本（如 Windows PowerShell 5.1 的 `.ps1`）。

**两条边界判据**：

- **短结论（索引）进 `MEMORY.md`；长论证进 `notes/`。**
- **`notes/` 两类**：任务结论是**活的**（随项目推进更新 → 同主题续更，只追加）；
  分析是**死的**（当时怎么想就该一直怎么想 → 只增不改）。

**贯穿原则**：`MEMORY` 只追加；`PRD` 改内容 ＋ 记变更；`notes/` 结论只追加、分析只增不改；
`docs/` `models/` `archive/` 里的**已有文件不改名**。

**文档变长了怎么办** —— 触发：找一条结论要滚超过 3 屏，或同一主题翻起来要来回跳。

| 条目 | 处置 |
|---|---|
| 仍会影响下一步判断的结论 | 留在主文件（哪怕它很旧） |
| 已收口、只作溯源用的事件记录 | 整段搬到 `notes/`，主文件留一行索引 |
| 已被推翻的旧决定 | **留在 `MEMORY.md`** ——「曾经错在哪」是防复发的信息 |

> **搬迁 ≠ 删除**：「只追加」约束的是内容不丢，不是位置不变。
> **规则类文件（本文件 / `SOUL.md`）**：废止的规则**不得裸留** —— 要么删（git 有历史），要么就地标注「已废止 → 现行为 X」。
> **Agent 不擅自动手**：发现该分层了，在回复里提请使用者，不要自己搬。

## 五、产物放哪（判据）

| 判据 | 落点 |
|---|---|
| **手写即交付** | `docs/` |
| **由源生成** | `dist/` —— **勿手改**，要改回源头重新生成 |
| **投影件**（由 MD 生成的人读视图） | `docs/`，但**投影字段不手改** |
| **对外定版快照** | `release/` —— 使用者手动从 `dist/` 复制；**AI 不代复制、不代刷新**；进版本库 |
| 图件 vs 模型本体 | 被文档引用的图件 → `assets/`；模型本体 → `models/`。**一个文件只放一处** |
| 退役但仍要翻到 | `archive/`（纯历史版本不必另存 —— 直接删，要用时从 git 取） |
| 临时文件 | `logs/`（不进版本库） |

> **根目录只住骨架文档、`README.md` 与 `.gitignore`，不放任何产物。**

## 六、命名规范

| 对象 | 规则 |
|---|---|
| **骨架 / 流程文档** | 英文大写、固定名不带日期（`AGENTS.md` `MEMORY.md` `PRD.md` `ROADMAP.md` `SOUL.md` `USER.md` `ACCEPTANCE.md` `CONTRACT.md`；`README.md` 按需） |
| **目录（骨架层）** | **英文小写**（硬规则，不做例外）；**禁止数字前缀 ＋ 同层中英混搭** |
| **骨架目录内部** | **本项目自定** —— 怎么分子目录、用什么语言、内部文件怎么命名，中英文都不限（本表另有约定的产出命名除外） |
| **内容文件名** | 默认**中文 ＋ 日期**（`餐桌架设计方案_20261004.html`）；**已有文件不改名** |
| **交付文档** | `{名称}_{YYYYMMDD}.html`（默认单文件 HTML）；**已有文件不改名**（改内容即可，避免断链） |
| **模型** | `{名称}_V{主.次.修}_{YYYYMMDD}` ＋ 原后缀；全局唯一、不覆盖；旧版移 `archive/`，`models/` 只留当前版 |
| **任务结论** | `{任务名}_结论_{YYYYMMDD}.md`，同主题续更 |
| **分析文档** | `{YYYYMMDD}_{子主题}.md`，只增不改 |
| **日期** | 一律 `YYYYMMDD` / `YYYYMM`，禁用 `yyMMdd` |

**骨架层不合规怎么处理**：一律列为「改名建议项」，**改不改由使用者拍板**；他拍板保留时在 §九 写明「由使用者决定」＋ 代价。

**扩展规则**：出现新类型产物时，**先在 §三 表里取**；表里没有的才按用途造词（优先通行小写英文名），
**一次只加一个**，并同步登记进 §三。**不要为了"以后可能用到"预建目录。**

## 七、默认工作流

1. **先查资料**：接需求先检索（`PRD.md` → `ROADMAP.md` → `MEMORY.md` → `notes/` → 产物目录），再分析。
2. **再分析**：结论要带依据；计算要给推理过程。
3. **不确定就说**：拿不准就明说，建议查哪份资料，不编造。
4. **动手前确认**：修改文件、对外沟通必须先请示 —— §一 已明确授权的除外。
5. **开场必读（最小集，不是通读）**：`AGENTS.md` §一 ／ §二 ／ §三 → `MEMORY.md` §2 最近两条 ＋ §4 待办，
   再对照 §三 表自查"到点该长什么"。其余按需查：`SOUL.md`、`PRD.md`、`ROADMAP.md`。
6. **复验**（主要任务完成后）：派子 Agent 做**独立交叉验证**（不参考你的结论）—— 核对关键数字与证据链、
   **找最能推翻它的反例**。至少 1 路；汇报里写明「派了几路 / 为什么」；**分歧点原样列出，不抹平**。
   > "主要任务"＝结论要进决策链的那些（调研收尾 / 方案对比 / PRD / 关键验收），不是每件小事都派。
   > **复验 ≠ 收尾自查**：前者是别人来质疑结论，后者是自己照镜子查自洽（见 §八）。
   > 平台没有子 Agent 能力时：**如实说明"无法独立复核"**，并至少做一次独立复算 ＋ 反例清单。

## 八、维护义务（任务收尾时执行）

**A · 自查（每个任务收尾都做）**

- **① 引用可达**：本次动过的路径逐个能打开（动过目录就逐个实测）
- **② 旧口径零残留**：改动的关键词全库 grep，逐处判「在用旧说法 → 改 / 在声明它已废 → 留」（历史归档除外）
- **③ 清单＝实物**：汇报的路径清单 ＝ 实际改动（**无遗漏、无虚构**）；两个方向都查 —— 该有的在，**多出来的也要登记**
- **④ 全库过目**：改动后逐文件过一遍，防"这处改了、别处还停在上轮"；表格列数一致、多张表逐行一致
- **⑤ 提交纪律**：点名 `git add`（提交前先看 `git status --short` 全清单），**不用 `git add -A`**；
  一次性产物（截图 / 转储 / 临时脚本）不进库
- **⑥ 状态表不失真**：§三 的 ☑/☐ 与磁盘现状一致
- 重要进展 / 决策 / 待办 → 追加 `MEMORY.md`；产物增减 → 同步 §二、§三
- **改动先比对 `PRD.md`**；冲突即为需求变更，记入其变更记录并同步受影响的产物

**B · 追平（动到进度类文件时做）**

- **① 三处一致**：`MEMORY.md` §2 最近一条 ↔ `ROADMAP.md` 状态列 ↔（若有）进度页的 `stage` / `next` / `risks`
- **② 日期一致**
- **③ 以谁为准**：不一致时以 `MEMORY.md` 为准；**唯一例外**是阶段路线 —— `ROADMAP.md` 建立后以它为准
- **④ 指针新建同步**：本轮新建了某份文件 → 把"它还没建时"的指针改成正式指针
- **⑤ 当轮记录落盘**：`notes/YYYYMMDD_主题.md`（只增不改）；口径级改动写「未实测记账」
