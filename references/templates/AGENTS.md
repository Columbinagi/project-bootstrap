## 二、目录结构

```
<项目名>/
├── README.md        对外门面：这是什么 ／ 怎么装 ／ 怎么用 ／ 当前版本与许可（**按需**：要分享 ／ 要上线 ／ 要给人看；**规矩不在这篇**）
├── AGENTS.md        项目指令：背景 + 领地 + 目录结构 + 产物顺序 + 写入规范 + 归档决策树
├── MEMORY.md        最新进展与已定决策（Agent 接手先读；按日期累积，最新在上）
├── PRD.md           需求基准：目标·约束·前提假设·验收·非目标·变更记录（**改动即需求变更**）
├── CONTRACT.md      线间接口 / 字段契约（**出现线间接口约定才建**；没有就不存在）
├── ROADMAP.md       计划层：关卡 Gate + 阶段表（**随阶段推进更新**）
├── ACCEPTANCE.md    验收记录：逐条对 `PRD.md` 验收基准的实测值（**进入验收前才建**）
├── SOUL.md          协作准则（含**协作方式**；**按区**附准则：内容区＝写作纪律 / 写代码＝编码准则）
├── USER.md          用户画像与雷区
├── .gitignore
│
├── engineering/     **工程区（立项即建）**：工具脚本 ＋ 进度页投影脚本（**不是空目录**）
├── content/         **内容区（按需）**：一切「源」（**内部结构由项目自己定**）
├── templates/       母版与模板（可派生）
├── skills/          技能（每技能一个子目录）
├── docs/            手写即交付的文档成品：报告 / 说明书 / 参考（含**项目进度页** —— 投影件，不手改）
│   ├── plans/       实施计划（带日期命名）
│   └── references/  参考资料
├── dist/            **由源生成的最终交付物（勿手改）** —— 要改回源头改 content/ 或 src/ 与 templates/，重新生成
├── release/         **对外定版快照** —— 使用者手动从 dist/ 复制（**默认同名**；要标日期就在尾部加 `_{YYYYMMDD}`）；**AI 不代复制、不代刷新**
├── assets/          被文档引用的图件：SVG / 图片 / 示意图 / 数据
├── models/          三维 / 实体模型文件本体
├── notes/           过程记录：任务结论（可续更）＋ 分析论证（只增不改）
├── archive/         退役区：不再维护但仍需被翻到的东西
├── logs/            临时文件与运行记录（**不进版本库**；首次需要时才建）
│
└── ── 以下**按代码角色**（**项目本体是软件**才有）──
    ├── src/         源码
    └── tests/       测试（随 src/ 走）
```

> ⚠️ **`src/` `tests/` 都在根目录**（上面那两行与 `content/` `engineering/` **平级**）——
> **不是 `engineering/` 的子目录**；`engineering/` 里只装工程工具（构建 / 校验 / 拼合 / **投影**那一类）。
> **"项目本体是软件" ≠ "把源码放进 `engineering/`"。**
>
> **`scripts/` 已退休**（v1.2.0）：辅助脚本一律进 `engineering/` —— 工程区立项即建，它永远用不上。

> **根目录只住骨架文档、`README.md`（按需门面）与 `.gitignore`，不放任何产物** —— 产物按 §五 落位。
>
> **命名规则见 §六 命名规范**（骨架层硬规则 / 内部由项目自定 —— 那边是**本文件里唯一一处**正文）。
>
> **骨架目录里面怎么分**（**方向，不是硬规则**）：一层一个维度 / 同类同处 / 能平铺就不分层 / 深度 ≤ 2–3 层 /
> 不留 `misc` `其他` `temp` 这类兜底目录；`dist/` 里别手工加层级、`archive/` 保持原样；
> 内部命名**中英文都行，但同一层保持一致**更好认。
>
> **边界判据**：模型**本体**进 `models/`，**被文档引用的图件**进 `assets/` —— 一个文件只放一处。
> **手写即交付** → `docs/`；**由源生成** → `dist/`；**投影件**（如项目进度页）→ `docs/`，**但不手改**（口径见 `versions.md` §八）。
>
> **从哪读起（给人）**：① `PRD.md` 看「要什么」→ ② `ROADMAP.md` 看「现在到哪、下一步干什么」→ ③ 要成品：手写的去 `docs/`、流水线出的去 `dist/`、对外定版去 `release/`。**其余几份是给 Agent 的交接文件，不必看。**

## 四、文档写入规范

| 什么时候发生 | 写进哪份 | 怎么写 |
|---|---|---|
| 需求 / 约束 / 验收 **确定或变更** | `PRD.md` | 改对应节 **＋ 变更记录加一行** |
| **接口 / 契约 确定或变更** | `CONTRACT.md`（或 `PRD.md` 对应节）＋ `PRD.md` 变更记录 | **开工产出前先定并冻结**；**改实现不登记，改契约才登记** |
| 阶段推进、关卡通过 | `ROADMAP.md` | 改状态列；卡点变了改「当前卡点」节 |
| **任何进展 / 决策 / 待办变化** | `MEMORY.md` | **按节追加到顶部**（最新在上），**不覆盖旧条目**：进展 / 结论 → §2；**已确认决策** → §3；**待办** → §4 |
| 目录 / 命名 / 规则 / 工作流变化 | `AGENTS.md` | 改对应节，同时检查 §二 目录树与 §三 表 |
| 用户偏好 / 雷区变化 | `USER.md` | 改对应节 |
| **任务结论**（同主题续更） | `notes/{任务名}_结论_{YYYYMMDD}.md` | **只追加，不改历史条目**；结论被推翻时，新条目写明「**取代第 N 条**」 |

> **编码**：文本一律 **UTF-8 无 BOM** —— BOM 会让解析器读不到文件头（配置 / 入口文件直接失效）。
> **唯一例外**：工具要求带 BOM 的脚本（如 Windows PowerShell 5.1 的 `.ps1`，无 BOM 会被按 ANSI 读、中文乱码）。
| 分析 / 论证 / 盘点（**只增不改**） | `notes/{YYYYMMDD}_{子主题}.md` | 新建文件；已有的一律不改 |
| 交付文档（报告 / 说明 / 参考） | `docs/{名称}_{YYYYMMDD}.html` | **默认单文件 HTML**；`USER.md` 另有格式偏好（md / PDF）从其偏好；**已有文件不改名** |
| **项目进度页**（投影件） | `docs/项目进度.html` | **改 MD → 由主控重跑 `engineering/progress_page.py`**（默认 dry-run，加 `--write` 才落盘）；**投影字段（`stage`／`stages`／`updated`）不手改**，**其余字段（`prompts`／`next`／`timeline`…）手改** |
| 完工实测值 | `ACCEPTANCE.md` | 逐条对 `PRD.md` 验收基准 |

**边界判据（一）：短结论（索引）进 `MEMORY.md`；长论证进 `notes/`。** `MEMORY.md` 里可直接链接到 `notes/` 的文件。

**边界判据（二）：`notes/` 里两类文件的区别 ——**

| 类 | 命名 | 规则 | 为什么 |
|---|---|---|---|
| **任务结论** | `{任务名}_结论_{YYYYMMDD}.md` | **同主题续更**（只追加） | 结论是**活的** —— 随项目推进而更新 |
| **分析 / 论证** | `{YYYYMMDD}_{子主题}.md` | **只增不改** | 分析是**死的** —— 当时怎么想的，就该一直是怎么想的 |

**贯穿原则**：`MEMORY` **只追加**；`PRD` **改内容 ＋ 记变更**；`notes/` **结论只追加、分析只增不改**；`docs/` `models/` `archive/` 里的**已有文件不改名**。

**长文档纪律（提示线，不是上限）**：**不设 KB 硬上限** —— 数字给不出依据，而且会与「`MEMORY.md` 只追加、不覆盖」直接冲突（迟早逼着删历史）。**改用体感判据 ＋ 分层动作。**

- **触发**：**找一条结论要滚超过 3 屏**，或**同一主题翻起来要来回跳**。
- **记录类文件（`MEMORY.md` / `notes/`）：只搬迁，不删除** —— 判据是「**是否还影响当前决策**」，**不是"有多旧"**：

| 条目 | 处置 |
|---|---|
| 仍会影响下一步判断的结论 | **留在主文件**（哪怕它很旧） |
| 已收口、只作溯源用的事件记录 | **整段搬迁**到 `notes/`，主文件留**一行索引** |
| **已被推翻的旧决定** | **留在 `MEMORY.md`** ——「曾经错在哪」是防复发的信息，别挪走 |

> **搬到哪（写死，避免歧义）**：**优先用本项目已有的归档区**（如 `项目归档.md` / 已有 `archive/`）；
> **没有才新建 `notes/`**。**不为搬运而新建与既有归档区并行的目录** —— 那是第二处漂移源。

- **规则类文件（本文件 / `SOUL.md`）另按一条**：废止的规则**不得裸留** —— 要么删（git 有历史），要么**就地标注「已废止 → 现行为 X」**（留着废止的规则，后来者会照着干）。

> **搬迁 ≠ 删除**：「只追加」约束的是**内容不丢**，不是**位置不变**。
> **Agent 不擅自动手**：发现该分层了，**在回复里提请用户**，不要自己搬。
> 主文件的代价是隐性的 —— 每次会话全量读入，成本线性增长、收益次线性。

## 六、命名规范

> **本节的命名规则是唯一正文**（§二 只放指针）；细则见 `versions.md` §三（skill 内参，落盘后删）。

| 对象 | 规则 |
|---|---|
| **骨架 / 流程文档** | 英文大写（`AGENTS.md` `MEMORY.md` `PRD.md` `ROADMAP.md` `SOUL.md` `USER.md` `ACCEPTANCE.md` `CONTRACT.md`），固定名不带日期，同主题续更；**`README.md`**（**按需门面**，同规则） |
| **目录（骨架层）** | **英文小写**（**硬规则，不做例外**）（`docs/` `docs/plans/` `docs/references/` `assets/` `models/` `notes/` `archive/` `logs/` `dist/` `release/` `templates/` `skills/`；**`engineering/` 立项即建**；`content/` 按需；**按代码角色**加 `src/` `tests/`）；**禁止数字前缀 ＋ 同层中英混搭** |
| **骨架目录内部** | **本项目自定** —— 里面怎么分子目录、用什么语言、内部文件怎么命名，**中英文都不限**（**本表另有约定的产出命名除外**：交付文档 / `notes/` 两类 / 模型） |
| **内容文件名** | 默认**中文 ＋ 日期**（`餐桌架设计方案_20261004.html`）；**已有文件不改名** |
| **交付文档** | `{名称}_{YYYYMMDD}.html`（**默认单文件 HTML**，`USER.md` 另有偏好从其偏好）；**已有文件不改名**（改内容即可，避免断链与旧分享失效） |
| **模型** | `{名称}_V{主.次.修}_{YYYYMMDD}` ＋ **原文件后缀**（`.html` / `.stl` / `.step` …），全局唯一、**不覆盖**；**旧版移 `archive/`，`models/` 只留当前版** |
| **任务结论** | `{任务名}_结论_{YYYYMMDD}.md`，同主题续更（**只追加，不改历史条目**） |
| **分析文档** | `{YYYYMMDD}_{子主题}.md`，**只增不改** |
| 日期 | 一律 `YYYYMMDD` / `YYYYMM`，禁用 `yyMMdd` |

**骨架层不合规怎么处理**：一律**列为「改名建议项」**（进差异清单）—— 要改就按 §八 逐个修链接并实测可达；
**改不改由使用者拍板**（他拍板保留时，在本文件 §九 写明"**由使用者决定**"）。

**扩展规则**：出现新类型产物时，**先在 `versions.md` §三 成分表里取**；表里没有的才按用途造词（优先通行小写英文名），**一次只加一个**，并同步登记进 §三 表。**不要为了"以后可能用到"预建目录。**

## 七、默认工作流

1. **先查资料**：接需求先检索（`PRD.md` → `ROADMAP.md` → `MEMORY.md` → `notes/` → 产物目录），再分析。
2. **再分析**：给结论要带依据；计算要给推理过程。
3. **不确定就说**：拿不准就明说"不确定"，建议查哪份资料，不编造。
4. **动手前确认**：修改文件、对外沟通，必须先请示 —— **§一 已明确授权的动作除外**。
5. **开场必读**：每次新会话先读 `AGENTS.md` → `MEMORY.md` → `SOUL.md`，再对照 §三 表自查"到点该长什么"。
   **协作分工**（角色位与边界）见 `SOUL.md` §协作方式；本项目实际怎么分工见 `USER.md` §工作方式。
6. **复验**（主要任务完成后）：派子 Agent 做**独立交叉验证**（**不参考你的结论**）—— 核对关键数字与证据链、
   检查结论是否被证据支撑、**找最能推翻它的反例**。**派几路由你判断 —— 至少 1 路**；完成汇报里写明「派了几路 / 为什么」；
   **分歧点原样列出，不抹平**。
   > **"主要任务"** ＝ 结论要进决策链的那些（调研收尾 / 方案对比 / PRD / 关键验收）—— **不是每件小事都派**。
   > **复验 ≠ 收尾自查**：前者是**别人来质疑结论**，后者是**自己照镜子查自洽**（见 §八）。
   > **平台没有子 Agent 能力时**：**如实说明"无法独立复核"**，并至少自己做一次独立复算 ＋ 反例清单 —— **不许假装已复核**。

## 八、维护义务（任务收尾时执行）

> **分两组，别互相等。** 多对话协作里 A 组通常**执行方**做、B 组通常**主控方**做；单对话项目**两组都过一遍**。

**A · 自查（自洽）—— 每个任务收尾都做**

- **① 引用可达**：本次动过的路径**逐个能打开**（动过目录就逐个实测）
- **② 旧口径零残留**：改动涉及的关键词**全库 grep**，逐处判"**在用旧说法 → 改** / **在声明它已废 → 留**"（历史归档除外）
- **③ 清单＝实物**：汇报的路径清单 ＝ **实际改动**（无遗漏、无虚构）；**两个方向都查** —— 该有的在，**多出来的也要登记**
- **④ 全库过目**：改动后**逐文件过一遍**，防"这处改了、别处还停在上轮"；表格**列数一致**、两张顺序表**逐行一致**
- **⑤ 提交纪律**：**点名 `git add`**（提交前先看 `git status --short` 全清单），**不用 `git add -A`**；
  **一次性产物**（截图 / 转储 / 临时脚本 / 别的对话的工作文件）**不进库** —— 放临时目录或写进 `.gitignore`
- 重要进展 / 决策 / 待办变化 → 追加 `MEMORY.md`
- 产物增减或位置变化 → 同步更新本文件 §二、§三（**含 §三 表里的 ☑ / ☐ 状态列**）与 `MEMORY.md`
- **改动 → 先比对 `PRD.md`**；冲突即为需求变更，记入其变更记录并同步受影响的产物
- 阶段推进 / 关卡变化 → 更新 `ROADMAP.md` 状态列与卡点节

**B · 追平（进度类文档）—— 动到进度类文件时做**

- **① 三处一致**：`MEMORY.md` §2 最近一条 ↔ `ROADMAP.md` 状态列 ↔（若有）项目进度页的 `stage` / `next` / `risks`
- **② 日期一致**：三处的日期对得上
- **③ 以谁为准**：不一致时**以 `MEMORY.md` 为准**，改另外两处并各记一笔。
  **唯一例外**：**阶段路线**（`stages`）在 `ROADMAP.md` 建立后**以它为准**（`SKILL.md` 第 6 步同款口径）—— 其余进度仍以 `MEMORY.md` 为准。
- **④ 指针新建同步**：本轮新建了某份文件 → 把"它还没建时"的指针**改成正式指针**（如 §一「当前阶段」改指 `ROADMAP.md` §三）；
  **同时**给 `MEMORY.md` 里那条「阶段路线」加 **【已移交 · 见 `ROADMAP.md` §二】** 标注（**不删**，留作回溯）
- **⑤ 人读页面同步**：说明页（口径与用法）与项目进度页（版本 ／ 阶段 ／ 最近改动）—— 口径变了改说明页，进度变了改进度页
- **⑥ 当轮记录落盘**：`notes/YYYYMMDD_主题.md`（**只增不改**）；口径级改动写「未实测记账」
