# 项目进度页（**立项即建**的按需产物）

> 本文件是**skill 侧**说明：什么时候建、落哪、谁维护、怎么与 MD 对账、要不要上脚本。
> **DATA 字段速查与页面整理规则不在这里复述** —— 正文在模板头部注释（`references/templates/progress.html` 顶部），
> **就地维护**（同一句话只写一处正文）。
> 落地提示：本文件是 **skill 侧说明**（讲"为什么、什么时候建、谁维护"），**本身不落项目**；
> 项目里实际落两件：`docs/项目进度.html`（页面）＋ `engineering/progress_page.py`（投影脚本）。
> 本文件里出现的 `references/...` 是**写 skill 时的内部出处**，项目侧不需要照抄。

---

## 一、什么时候建

**立项即建** —— 随骨架文档一起交付。它是使用者"从 0 搭项目时，第一步就能验收"的那个人读视图：
打开就知道**现在在哪、下一步干什么**。

> 它**不再是**"项目进入多阶段才建、不建不算缺陷"的按需产物 —— v1.2.0 起改为立项即建。

## 二、落在哪、叫什么

`docs/项目进度.html` —— **文件名固定、不带日期**（<20261018> 起；它是**长期在更**的页，不按日期归档）；「建档日」**写进页内**（填一次，如 `project.tagline`），不再占文件名。**落盘后此名不改**（改名会断链、旧分享失效）。
落点依据：**手写即交付 → `docs/`**；它是**投影件**（人读视图），也进 `docs/`，**投影字段（`stage`／`stages`）不手改，其余字段手改**（见 `versions.md` §八）。

## 三、谁维护

- **主控 / 项目维护方**维护；**执行方修改需使用者授权并在 `MEMORY.md` 留痕**。
- **投影脚本只有主控能触发** —— 这条要写进项目 `AGENTS.md` §九，并在脚本头部注明。

## 四、数据关系（**单向投影，永不反向**）

| 关系 | 规矩 |
|---|---|
| **权威源** | `AGENTS.md` / `MEMORY.md` / `ROADMAP.md` 等 MD |
| **页面** | **投影**：不产生新事实、**不反向写回** |
| **更新顺序** | **先改 MD → 再刷新页面**（重跑脚本，或手工改 `DATA`） |
| **冲突** | **以 MD 为准** |
| **`DATA.updated`** | 数据截止时间，**必须与本次改动同步**（脚本会自动刷新） |

**阶段路线的权威链**（v1.2.0）：

1. **前期**（还没有 `ROADMAP.md`）→ 权威在 **`MEMORY.md` §2 的一条**：
   `阶段路线（起点，可增删改名）：概念 → 调研 → 立项 → 设计 → 执行 → 验收；当前：概念`
2. **`ROADMAP.md` 建立后**（＝ PRD 经用户审核通过）→ **权威转交 `ROADMAP.md` §二 阶段表**；
   `MEMORY.md` 那条按"只追加"留作历史。
3. **移交动作（建立 `ROADMAP.md` 的同一轮做）**：给 `MEMORY.md` 那条加 **【已移交 · 见 `ROADMAP.md` §二】** 标注（**不删** —— 起点清单留作回溯）；
   此后**脚本只读 ROADMAP**（它存在但 §二 缺失 / 为空 ⇒ 报错不猜）；**两边说法冲突时以 ROADMAP 为准**。
4. 页面 `stage` / `stages` 永远只是这两处的**投影**。

## 五、模板三层（**固定 / 占位 / 可换**）

> ⚠️ **模板 ＝ 使用者拍板的规范版（v2，<20261018> 更新）** —— `references/templates/progress.html`（命名去日期、占位符同步；**改模板本体要先取得使用者同意** —— 本次即经同意）。
> 日常要改的是**复制出来的那一份成品页**，不是模板。脚本也**不依赖模板里的任何标记**（它只认 `var DATA = {…};` 这个数据区）。

| 层 | 内容 | 规矩 |
|---|---|---|
| **固定** | 区块顺序、字段名、状态枚举 `done` / `doing` / `todo`、空节隐藏（**任务链与提示词、需要你做的除外**：空时给空态提示）、**零外部请求**、复制按钮、480px 与深色基线、**单向投影** | **不要为了"好看"破例** |
| **占位** | `project` `stage` `topics` `stages` `batchGroups` `batch` `prompts` `timeline` `next` `files` `risks` | 按项目替换；字段含义见**模板头部注释** |
| **可换** | 品牌色、标签文案、页脚说明 | **不做多套主题 / 不做皮肤** |

> ⚠️ **`timeline` 数组必须「最早在前、最新在后」**（**<20261018> 立的坑**）——
> 模板的折叠逻辑取的是数组**尾部**当"最近 `timelineRecent` 轮"（`renderTimeline`：`start = list.length - recent`），
> 而它的字段说明表**只写了"默认显示最近几条"、没写顺序**。**填成"最新在前" ⇒ 默认显示的是最旧的几条、把最新的折叠起来**，
> 与它自己写的"最近 N 轮"正好相反（本仓库自己的进度页就这么错过一次，核验轮才挖出来）。
> 其余数组（`stages` `batch` `topics` …）**没有这个约束** —— 模板只对 `timeline` 做切片。

> ⚠️ **两条铁律**（有实证教训 —— 改坏过一次，整页样式全失效）：
> ① **不要在 CSS 注释块里再写 `/*` 或 `*/`** —— 注释会**提前闭合**，后面的样式表变成垃圾，
> 页面**背景、卡片、颜色全没**，而页面**照样打得开**，肉眼很难发现；
> ② **改完必须真渲染一遍**（无头浏览器截图即可）：**背景色与品牌色像素必须在位**。
> 判断法：截图里若"灰底几乎为 0、只剩白底黑字"，就是样式坏了。

## 六、结构校验（**只看结构，不看语义**）

阶段序列必须满足四条：

1. **2–12 段**（**这是模板的呈现约束，不是流程规则** —— 段数多了那条横向路线就没法看）；
2. **只能有一个 `doing`**；
3. **`done` 在前**；
4. **名称唯一**。

**内容由 Agent 按项目定**：允许**增删 / 改名 / 粗粒度或细粒度**；**偏离要在 `ROADMAP.md` 说明理由**。

**示例（起点，不是轨道）** —— 只给名称序列，**不给"每阶段该做什么"**：

- 软件：准备 → 设计 → 实现 → 联调 → 验收
- 内容：素材 → 起草 → 校对 → 发布
- 工程：定契约 → 搭管线 → 试跑 → 交接

**常用阶段名**（当起点用）：准备 / 概念 / 调研 / 设计 / 实现 / 验证 / 联调 / 试点 / 发布 / 收口。

> **照抄不算错，但照抄也不是目标** —— 阶段要能从**本项目自己的需求**推出来。

> **不做「场景预设体系」**（<20261018> 使用者口径）：本节只给**起点清单**与**示例**（均明标「不是轨道」）—— **不建预设库、不做成套的场景预设**；阶段要能从**项目自己的需求**推出来，这层留白是有意的、不是缺件。

## 七、交付前自检（**三条，一条不能省**）

> 交付的必须是**填好的成品页**，不是模板本身 —— **把模板当成品交出去 ＝ 交了一张空壳**（这条有实证教训）。

| # | 查什么 | 判据 |
|---|---|---|
| 1 | **占位符替换完** | **数据区里 `{{` 计数 ＝ 0**；全页 `{{` 只应剩 **2 处**（都在说明文字里，不渲染） |
| 2 | **数据区能被 JS 解析** | 页面**真的渲染出内容**（页头有项目名、阶段路线有节点、三个数字有值）。**最稳的查法**：把 `var DATA = {…};` 抠出来喂给 `node` 跑一遍 —— **语法错一处，整页全空**（只剩静态小标题） |
| 3 | **跑一次脚本 dry-run** | `python engineering/progress_page.py .` → 看它将改哪几处；确认无误再 `--write` |

> ⚠️ **为什么第 2 条非查不可**：填占位符时**多填/少填一个值就会整体错位**，把长文本填进单引号字段 ⇒
> **JS 语法错误 ⇒ 整页只有静态小标题、内容全空**。这种页面"打得开、看着像正常"，**只有真渲染一遍才看得出来**。

## 八、投影脚本（`engineering/progress_page.py`）

**五条约束**（同时写在脚本头部注释里）：

1. **只读 MD** —— 绝不写回任何 MD；
2. **幂等** —— 同一份输入跑两次，输出**逐字节相同**（因此"投影内容没变"时整页一个字节都不动）；
3. **默认 dry-run** —— 只打印"将要改哪几处"，加 `--write` 才落盘；
4. **报错不猜** —— 解析失败就**非零退出**，**绝不产出半成品页面**；
5. **只有主控能触发**。

**投影范围（v1）**：只接管页面数据区里**两个字段**（`stage` / `stages`）＋ `DATA.updated`；
其余区块（`topics` / `batch` / `prompts` / `timeline` / `next` / `files` / `risks`）**仍由主控手工维护**。
**脚本不依赖模板里的任何标记** —— 它只认 `var DATA = {` … `};` 这个数据区，在里面按结构定位 `stage:` 与 `stages:`。

> **提示词的「唯一正文」＝ 本页 `prompts.current`**：当轮在对话里贴的提示词必须与它**逐字同版**；
> **已派发的立即移出 `current`**（移入 `used`；全文要留就归档到 `notes/`）—— 否则会出现两份都自称"最新版"的提示词。
> **它与「提示词不另外建文件」不冲突**：`prompts.current` 就是正文（写在页面里），**不另建一份 md**；
> `notes/` 里的只是归档副本，**不作正文**。

> **更新节奏**：**每完成一个批次（一次收尾）就刷新一次**，不必每改一个文件就刷；也别等"里程碑"——
> 各项目对里程碑的定义不一，等它＝页面长期滞后（`AGENTS.md` §八 的「B 追平」核对兜底）。

> **刷新后体检（三条，专治"没同步 / 没清理"）**：
> ① `next.ready` **只放未完成项** —— `state` 不得是「已完成 ／ 已定 ／ 已移出」（做完的进 `timeline` 或 `next.decided`）；
> ② `prompts.current` 与 `used` **不重复** —— 已派发的**立即移出**，`current` 只留"还没用 / 正在用"的那一份；
> ③ `updated` **不得早于最新一次提交** —— 页面比仓库旧，就是没同步。
> **`updated` 属手写**：每次收尾手填；脚本只在 `stage`／`stages` 真的变了时才顺带刷新（幂等要求），**别指望它替你记时间**。

**用法**：

```bash
python engineering/progress_page.py .            # dry-run：看将要改哪几处
python engineering/progress_page.py . --write    # 落盘
python engineering/progress_page.py . --page docs/项目进度.html --write
```

**没有 Python 时**：**退回"主控手工改页面 `DATA` 区"**，并在汇报里**如实说明**（照"无 git 时跳过并说明"的先例）。
**脚本不是 bootstrap 的必答题** —— 骨架照建，页面照交付，只是刷新方式退回手工。
