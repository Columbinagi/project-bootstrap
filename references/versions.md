# 目录与落点规则

> **本文件是「建什么、放哪、什么时候建」的唯一正文。** 其他文件只放指针，**不复制**本文件内容。
> 唯一允许的副本：`references/templates/AGENTS.md` §三 的那张表（要随项目落地），
> 它是本文 §四 的**逐行副本**，由 `tools/lint.py` 比对 —— 不一致即报错。
>
> 历次变更见 `references/changelog.md`（历史，执行时不必读）。

---

## 一、按需规则（**无例外**）

**立项只建四份骨架文档 ＋ `git init` ＋ `.gitignore`；`PRD.md` 在同一轮的第 5 步写（不建空文件）。其余一律等触发条件满足再建。**

| 触发条件 | 才建 |
|---|---|
| 立项（第一次对话） | `AGENTS.md` `MEMORY.md` `USER.md` `SOUL.md` ＋ `.gitignore` ＋ git |
| 立项的第 5 步（内容写完才落盘） | `PRD.md` —— **不建空文件** |
| PRD 经使用者审核通过 | `ROADMAP.md` |
| 出现线间接口约定（**产出依赖它的内容之前**） | 契约：并入 `PRD.md` 一节，或独立 `CONTRACT.md` ＋ PRD 放指针（见 §九） |
| 出现第一份内容源 | `content/` |
| 项目本体是软件 | `src/` `tests/` |
| 出现第一份工具脚本 | `engineering/` |
| 要给人看进度 / 交付文档 | `docs/` ＋ 进度页（见 §六 进度页） |
| 进入验收 | `ACCEPTANCE.md` |
| 要对外分享 / 上线 | `README.md` |
| 其余目录 | 见 §三 成分表逐项触发条件 |

> **不存在"立项即建"的目录。** 空目录不是"准备好"，是负债：它让人以为里面有东西，也让"该不该建"永远说不清。
> 唯一看似例外的情况是工具脚本 —— 但它建在**第一个脚本真的出现**的时候，不是开工时。

## 二、代码放哪（**按角色归位**，不问使用者）

| 代码的角色 | 住哪 |
|---|---|
| 项目本体是软件（库 / 框架 / 应用源码） | `src/` ＋ `tests/`（**根目录一级**，与 `content/` `engineering/` 平级） |
| 工具脚本（构建、校验、转换、拼合、投影、本地服务） | `engineering/` |
| 只有零星脚本、还没成规模 | 同样进 `engineering/` —— **不要散在根目录** |

> **"项目本体是软件" ≠ "把源码塞进 `engineering/`"**：两者可以并存，源码进 `src/`，它自己的构建脚本仍进 `engineering/`。
> **`scripts/` 已退休**（v1.2.0）：一个职能只留一个落点。

**三件事按区表述**（有几块就写几块，写进项目 `AGENTS.md` §一）：

| # | 事项 | 怎么写 |
|---|---|---|
| ① | 准则附录 | **按区并入** `SOUL.md`：内容区 → `guidelines/SOUL-content.md`；写代码 → `guidelines/SOUL-code.md`（本体是软件）或 `SOUL-code-lite.md`（只有工具脚本）。**不写就不附**，不另建文件 |
| ② | 授权范围（默值） | 内容区不引入代码、确需写脚本先问；工程区可自行写工具脚本。与 `USER.md` 冲突时**以 `USER.md` 为准** |
| ③ | 验收形态 | **按区各写 ＋ 一条成品总验收**；判据必须**可被外部核对**（不能写"脚本跑通了"） |

## 三、成分表（**全库一张**）

> **先在表里取；表里没有的**才按用途造词（§六）。"什么时候长"＝触发条件，**不等于"开工就建"**。
> 行业主流目录名一字不改（`docs/` `assets/` `notes/` `src/` `tests/` `dist/` …）。

| 产物 | 干什么 | 什么时候长 |
|---|---|---|

| `MEMORY.md` | **进度与决策索引**（接手先读；完整论证放 `notes/`） | 立项 |
| `USER.md` | 使用者画像（偏好、雷区、提问偏好、项目默认根目录） | 立项 |
| `SOUL.md` | 协作准则（＋按区并入的准则附录） | 立项 |
| `PRD.md` | **需求基准**：目标、约束、前提假设、验收基准、非目标、变更记录 | 立项（第 5 步写） |
| `ROADMAP.md` | 计划与关卡 G1–G4、阶段表、当前卡点 | **PRD 经使用者审核通过** |
| `CONTRACT.md` | 线间字段契约（**只在两个区之间真有硬约束时**） | 出现线间接口约定，**产出之前** |
| `ACCEPTANCE.md` | 验收记录（逐条对 PRD 验收基准的实测值） | 进入验收前 |
| `README.md` | 对外门面（这是什么 / 怎么装 / 怎么用 / 当前版本 / 许可） | **按需**：要分享、要上线、要给人看；**不建不算缺陷** |

> **根目录只住骨架文档、`README.md` 与 `.gitignore`** —— 不放任何产物（§八）。
> **项目的规矩只有一处正文＝`AGENTS.md`**，`README.md` 不抄规矩。

### 三.2 目录

| 产物 | 放什么 | 什么时候长 |
|---|---|---|
| `content/` | 内容区：一切「源」（正文、规范、清单、配置）—— **内部结构由项目自己定** | 出现第一份内容源 |
| `engineering/` | 工程区：工具脚本（构建、校验、转换、拼合、投影、本地服务） | 出现第一份工具脚本 |
| `src/` `tests/` | 主要源码 / 测试（**根目录一级**） | 项目本体是软件 |
| `docs/` | **手写即交付**的文档成品（报告、说明、参考）＋ **投影件**（人读视图）。默认单文件 HTML（`USER.md` 另有偏好从其偏好） | 出现第一份文档类交付物 |
| `docs/plans/` | 实施计划（一次性、带日期） | 出现第一份计划 |
| `docs/references/` | 外部资料、快照 | 出现第一份参考资料 |
| `notes/` | 过程记录（结论续更 ＋ 分析只增） | 出现第一份过程记录 |
| `assets/` | **被文档引用的图件**（SVG、图片、示意图、数据） | 出现第一份图件 |
| `models/` | 三维 / 实体模型**本体** | 出现第一份模型 |
| `templates/` | 可派生的模板类资产（母版、样板页、模板文件） | 出现第一份模板类资产 |
| `skills/` | 每个技能一个子目录（内含各自 `SKILL.md`） | 出现第一个技能 |
| `dist/` | **由源生成**的最终交付物（勿手改） | 出现第一份流水线产物 |
| `release/` | **使用者手动**定版的对外快照（从 `dist/` 复制） | 需要对外发布时 |
| `archive/` | 不再维护、但仍需被人一眼翻到 | 出现第一件需退役的 |
| `logs/` | 临时文件与运行记录（`.gitignore` 排除） | 首次产生临时文件 |

> **`docs/` 与 `dist/` 的判据**：手写即交付 → `docs/`；由源生成 → `dist/`。
> **`models/` 与 `assets/` 的判据**：模型本体 → `models/`；被文档引用的图件 → `assets/`。**一个文件只放一处。**
> **骨架目录内部不管**：`content/` `docs/` 里怎么分子目录、用什么语言，由项目自己定（方向见 §三.3）。

### 三.3 骨架目录内部怎么分（**方向，不是硬规则**）

> **不达标不算缺陷、不列差异清单**；违背的代价是"越来越难找东西"，由项目自己权衡。

1. **一层一个维度**：同一层只按一个标准分（按类型 / 主题 / 阶段，选一个）。
2. **同类同处**：同一类东西只放一处；出现第二处，就是漂移的开始。
3. **能平铺就不分层**：一类东西不到 5–7 个文件时，别急着建子目录。
4. **深度 ≤ 2–3 层**：再深说明分类维度选错了。
5. **看名知意**：不用 `1_` `2_` 数字前缀，不留 `misc/` `其他/` `temp/` 兜底目录。
6. **同类同格式**：同一类文件用同一种命名格式（带不带日期 / 版本号，一类定一次）。
7. **骨架目录内部**同一层的命名语言一致（全中文或全英文）—— 这条**只管内部**，不是骨架层的零豁免项。
8. **两个特例**：`dist/` 里别手工加层级（生成器说了算）；`archive/` 保持搬进来时的原样。

### 三.4 命名规则（**只管骨架层**）

**硬规则，零豁免**：① 成分表里的目录名用**英文小写**；② 根目录骨架文档用**英文大写**；③ 同一层不出现中英混搭的目录名。

- **骨架目录内部**（子目录、内部文件、用什么语言）→ **由项目自己定**，不属命名规则管辖。
- **内容文件名**（默值）：中文 ＋ 日期（`餐桌架设计方案_20261004.html`）；**已有文件不改名**。
- 不合规的一律**列差异项、建议改英文**，**改不改由使用者批**（执行口径见 `realign.md` 第 2 步）。

## 五、开工时到底建哪些

| 时机 | 建什么 |
|---|---|
| **开工（第一次对话）** | 四份骨架文档（`AGENTS` `MEMORY` `USER` `SOUL`）＋ `.gitignore` ＋ `git init`；**`PRD.md` 在同一轮第 5 步写** |
| **开工前（有线间接口时）** | 接口 / 字段契约先定并冻结（落 `CONTRACT.md` 或 `PRD.md` 对应节） |

## 六、扩展规则与新产物

**不要为了"以后可能用到"预先建目录。** 出现新类型产物时：

1. **先在 §三 成分表里取** —— 有同类落点就用它；表里没有才按用途造词（优先通行小写英文名）
2. **一次只加一个**
3. **同步登记进项目 `AGENTS.md` 的「产物长出来的顺序」表**

| 候选 | 用途 | 什么时候才加 |
|---|---|---|
| `config/` | 配置文件 | 顶层有多份配置时（否则放代码目录内） |
| `data/` | 数据集 / 输入数据 | 真有数据时（内容源优先 `content/`） |
| `deploy/` | 部署、Docker、CI、IaC | 要部署时 |
| `examples/` | 对外示例 | 库 / 工具类项目 |
| `bin/` `tools/` | 可执行入口 / 工具 | ❌ 与 `engineering/` 重叠，不加 |
| `devlog/` | 开发日志 | ❌ 已被 `notes/` 覆盖 |
| `build/` `node_modules/` | 构建缓存 / 依赖 | ❌ 不进库，`.gitignore` 排除 |

**`archive/` 与 git 的分工**：git 保存所有历史；`archive/` 只放**不再维护、但仍需被人一眼翻到**的东西。
**推论**：纯历史版本不必另存文件 —— 直接删，要用时从 git 取。

### 进度页（**按需**）

要给人看进度时才建：`docs/项目进度.html`（成品）＋ `engineering/progress_page.py`（投影脚本）。
模板与脚本在 `references/templates/`，说明见 `references/progress-page.md`。
**不建不算缺陷** —— 一个刚立项、只有五份文档的项目，最不需要的就是一张没人看的页面。

## 七、文档变长了怎么办（**提示线，不是上限**）

**触发（体感判据，不用数字）**：**找一条结论要滚超过 3 屏**，或**同一主题翻起来要来回跳**。

**记录类文件（`MEMORY.md` / `notes/`）：只搬迁，不删除** —— 判据是「**是否还影响当前决策**」，不是"有多旧"：

| 条目 | 处置 |
|---|---|
| 仍会影响下一步判断的结论 | **留在主文件**（哪怕它很旧） |
| 已收口、只作溯源用的事件记录 | **整段搬迁**到 `notes/`，主文件留一行索引 |
| 已被推翻的旧决定 | **必须留在 `MEMORY.md`** ——「曾经错在哪」是防复发的信息 |

**规则类文件（`AGENTS.md` / `SOUL.md`）另按一条**：废止的规则**不得裸留** —— 要么删（git 有历史），要么**就地标注「已废止 → 现行为 X」**。

> **搬迁 ≠ 删除**：「只追加」约束的是内容不丢，不是位置不变。
> **Agent 不擅自动手**：发现该分层了，在回复里提请使用者，不要自己搬。

## 八、产物落点（**全项目只有一种放法**）

| 落点 | 放什么 | 规矩 |
|---|---|---|
| **根目录** | 只住骨架文档、`README.md`、`.gitignore` | **不放任何产物** |
| `docs/` | **手写即交付**的文档成品 ＋ **投影件**（由脚本从 MD 生成的人读视图） | 投影件不手改 —— 改源头 MD 后重跑脚本 |
| `dist/` | **由源生成**的最终交付物（流水线产物） | **勿手改**；默认不进版本库（可由源重生成） |
| `release/` | **使用者手动**定版的对外快照 | 从 `dist/` 复制、**默认同名不改**（要标日期只在尾部加 `_{YYYYMMDD}`）；**AI 不代复制、不代刷新**；**进版本库** |

> **判据**：由源生成 → `dist/`；手写即交付 → `docs/`；投影件 → `docs/` 但不手改。
> **不要让产物和源在同一层无标记地平铺**，也不要为了分享方便把产物留在根目录。

## 九、PRD 与 AGENTS 的分工（**PRD 不省**）

| | 回答的问题 | 归属判据 |
|---|---|---|
| `PRD.md` | **做什么、做到什么算成** | 对「结果」的承诺 |
| `AGENTS.md` | **怎么干活** | 对「过程」的约定 |

**一句话判定线**：这句话改动时，**需不需要登记变更记录？** 需要 → `PRD.md`；不需要 → `AGENTS.md`。
**两条规则不一致时以判定线为准** —— 主题归类是描述，留痕需求是后果。

**状态类字段按变更频率分层**：天级（进展 / 待办 / 卡点）→ `MEMORY.md`；周级（关卡 / 阶段）→ `ROADMAP.md`；
月级（领地 / 目录 / 命名 / 授权）→ `AGENTS.md`；需求与验收基准 → `PRD.md`。
**跨层只写指针**，粒度到「节」不到「文件」，一个字段最多指一处。**低频 ≠ 可省**。

**接口 / 契约归哪**：属 `PRD.md` 的职能域（改它要登记变更）。契约短 → `PRD.md` 独立成节；
被两个区反复引用 → 独立 `CONTRACT.md`，**`PRD.md` 只放指针，变更记录仍归 `PRD.md`**。
**冻结边界**：契约冻结之后，改实现（渲染层 / 工具）不算需求变更，改契约才算。
**不预建，但先定**：只有真存在线间接口时才建 —— 但一旦存在，必须在产出依赖它的内容之前定下来并冻结。
**目录可以后长，接口不能后补**：先写一百条内容再改契约 ＝ 前面全部返工。

> **PRD 不省的理由**：它的独有职能是「变更的比较基准」。基准散落在 AGENTS / MEMORY / ROADMAP 里，就等于没有基准 ——
> 改设计时要去三处拼，其中一份被单独更新就静默漂移。

## 十、版本制度

> **改了就得升，哪怕只改一句措辞。** 同一版本号对应两份不同正文，就等于没有版本号。

| 改了什么 | 升哪一位 |
|---|---|
| **判定结果会变**：判据新增 / 废弃、管辖范围变、验收基准变、流程硬要求变 | **次版本 +1** |
